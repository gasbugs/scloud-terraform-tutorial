# SAT와 AI 학습 운영 · 20분 영상 7편

**제작안: 7편 × 20분 = 140분.** 실제 녹화 시간이 확인된 완성 영상은 아직 없다. 매 편은 하나의 고유한 질문을 해결하며 강사의 설명과 증거 화면으로 구성한다. 토의·학생 발표·개별 작업 대기 시간은 영상 길이에 넣지 않는다.

| 편 | 고유한 질문 | 새로 다룰 콘텐츠 | 근거 화면·파일 |
|---:|---|---|---|
| 1 | AI 학습 전체에서 SAT는 어디를 맡는가? | 데이터·학습·검증·활용의 단계, 사용자와 플랫폼의 책임 | 상품설명회 전사, Job 흐름도 |
| 2 | 재현 가능한 입력과 출력은 어떻게 추적하는가? | 데이터·모델 revision, train/validation/test, 매니페스트, 원본·마운트·출력 경로 | 원본 demo input-manifest.json, run-config.json, 결과 파일 |
| 3 | On-Demand Job 설정은 어떻게 검토하는가? | GPU·노드·이미지·Command·스토리지의 의존성, 설정 오류 사례 | 저장된 On-Demand 폼과 실제 Job 설정 |
| 4 | Spot에서 무엇이 중단되고 어떻게 재개되는가? | 자원 회수, GPU 하드웨어 장애, 체크포인트 저장·복원, Failover 적용 범위 | 저장된 Spot 폼, 제품 설명, checkpoint-10 파일 |
| 5 | Job 실행이 성공했는지 어떻게 진단하는가? | 상태→상세→로그→모니터링의 순서, 원본 demo·텍스트 Job 로그, 오류와 경고 구분 | 두 Job의 실제 상세·로그, 미보존 시계열 |
| 6 | 학습 결과가 좋아졌다고 말할 수 있는가? | 텍스트·이미지 전후 지표, validation/test 차이, 이미지 혼동행렬, 원본 demo의 개선 없음, 모델 파일 | comparison.json·before/after.json·confusion_matrix.json·어댑터 |
| 7 | 어떤 관리형 학습 서비스를 선택할 것인가? | SAT·SageMaker·Bedrock의 코드 자유도, 스토리지, Spot, 운영·이동성·비용 | 공식 문서 비교표와 세 요구사항 사례 |

## 편별 경계

- 1편은 전체 흐름과 책임만 다룬다. 제품별 선택은 7편에서 결정한다.
- 2편은 실험의 **입력·출력과 재현성**을 다룬다. 폼 조작은 3편이다.
- 4편은 **중단과 복구 조건**을, 5편은 **실행 기록으로 원인을 진단하는 방법**을 다룬다.
- 5편은 로그와 상태의 증거를 읽는다. 정확도·혼동행렬·모델 품질은 6편이다.
- 원본 demo에서 학습·업로드가 완료되어도 20개 샘플 평가 지표는 개선되지 않았다. 이 반례를 6편의 핵심 사례로 쓴다.

## 20분 판정 절차

각 편의 콘텐츠를 4개 장면으로 구성하고 장면마다 새로운 개념·사례·근거 파일이 있는지 검사한다. 근거가 부족한 편은 대사를 늘리지 않고 다른 편에 합친다. [녹화 구성안](TEACHING_GUIDE.md)으로 한 편을 먼저 시범 녹화해 실제 재생 시간과 정보 밀도를 측정한다. 20분이 되지 않으면 검증 가능한 새로운 콘텐츠를 확보하거나 편수를 더 줄인다. 무음, 반복 설명, 시청자 응답 대기로 길이를 맞추지 않는다.

로컬 화면은 교육용 구현이며 결과는 보존된 AWS G6 실행 기록이다. SCP SAT에서 실행한 결과라고 소개하지 않는다. 서비스 비교의 근거와 미확인 조건은 [SERVICE_COMPARISON.md](SERVICE_COMPARISON.md)에 둔다.
