# 녹화용 콘텐츠·화면 구성안 · 6편

**편당 목표 20분, 총 120분.** 시각은 편집 목표이며 아직 실제 녹화로 확인되지 않았다. 각 장면은 강사 설명과 화면 시연이다. 시청자 답변이나 실습 완료를 기다리지 않는다. 이론은 AI 학습 전체를 다루되 화면 실습은 Training Job만 사용한다.

## 녹화 전 공통 점검

[Job 목록](http://127.0.0.1:8080/local#jobs), [원본 demo](http://127.0.0.1:8080/local#jobs/b669419947d55d6991620cdf9bbcaa1f/details), [텍스트 Job](http://127.0.0.1:8080/local#jobs/2dd8760c5b7b55dc8d440c0d18ad2a4e/details), [이미지 Job](http://127.0.0.1:8080/local#jobs/cb0e433e77965ac9ad283d14027ed2df/details), [Training Job 폼](http://127.0.0.1:8080/reference/job-new.html), [Spot 폼](http://127.0.0.1:8080/reference/job-spot.html)을 연다. 저장된 폼은 실제 SCP 백엔드에 연결되지 않으므로 생성 버튼을 누르지 않는다. 화면의 H100 80GB는 SAT 실습 시나리오 명칭이다. 보존 결과 중 로컬에 가져온 Job은 AWS G6/L4 실행 기록이며, demo-main.zip에는 별도의 H100 80GB 참고 기록이 있다. 이를 같은 GPU에서 실행한 결과로 소개하지 않는다. 실제 SCP Job 실행 검증은 이 과정의 완료 조건이 아니다. 녹화 직전에 화면 값과 파일 링크를 다시 확인한다.

## 1편 · AI 학습 흐름과 재현성

**고유 목표:** 학습 Job 앞뒤의 의사결정과 동일 실험을 다시 설명하는 데 필요한 정보를 이해한다. 실제 폼 조작은 2편에서 시작한다.

| 목표 시각 | 새 콘텐츠와 화면 |
|---|---|
| 00:00–05:00 | 데이터 수집·정제→분할→학습→검증→test→모델 저장→추론 활용 흐름도를 그린다. SAT가 GPU Job의 실행 흐름을 관리해도 데이터 의미와 코드·결과의 검증은 사용자 책임임을 구분한다. |
| 05:00–10:00 | train은 가중치 갱신, validation은 선택, test는 최종 평가라는 역할을 설명한다. test 결과를 반복해서 보고 설정을 바꾸면 독립 평가의 의미가 약해지는 반례를 제시한다. |
| 10:00–15:00 | 원본 demo input-manifest.json의 데이터·모델 revision, seed 42, train 2,700·validation 540·test 540건과 run-config.json의 max_steps 10·eval_samples 20을 보여 준다. 번들 전체 표본 수와 이번 짧은 실행의 평가 표본을 구별한다. |
| 15:00–20:00 | 같은 Job 이름으로 데이터 revision, 기반 모델 revision 또는 seed만 바꾼 가상 비교표를 완성한다. 실제 두 번째 실행은 없으므로 점수 변화는 만들지 않는다. 재현 기록에 남길 데이터·모델 버전, 이미지·명령, seed, 평가 분할을 정리한다. |

**출처 경계:** SAT 상품설명회는 관리형 학습 흐름의 배경 자료다. input-manifest와 run-config는 AWS G6 원본 demo의 보존 파일이다. 가상 변경 사례는 실제 재실행 결과가 아니다.

## 2편 · Training Job의 입력·출력과 생성 설정

**고유 목표:** 스토리지 경로와 실행 설정을 하나의 Training Job으로 연결한다. On-Demand는 학습 형태 예시이며 별도 기능이 아니다.

| 목표 시각 | 새 콘텐츠와 화면 |
|---|---|
| 00:00–05:00 | 원본 demo의 입력 매니페스트에서 dataset/train.jsonl과 기반 모델 model/model.safetensors를 찾는다. run-config.json의 input_uri와 output_uri를 구별하고, 이 AWS S3 주소를 SCP Object Storage 주소로 바꿔 설명하지 않는다. |
| 05:00–10:00 | 원본 스토리지→컨테이너 내부 /work→이미지 속 코드·Command→결과 저장의 흐름을 원본 Job 상세에 매핑한다. 입력 기반 모델과 출력 adapter/adapter_model.safetensors의 역할을 구별한다. |
| 10:00–15:00 | 저장된 Training Job 생성 화면에서 학습 형태 On-Demand, Job명, GPU·노드·Shared Memory, 이미지·레지스트리 권한, Command, Volume/Object Storage를 순서대로 읽는다. 단일 노드를 여러 노드로 바꾼다고 코드가 자동 분산되는 것은 아님을 설명한다. |
| 15:00–20:00 | 제출 전 요약에서 이미지에 코드가 있는지, Command가 그 파일을 부르는지, 입력 마운트와 출력 경로가 맞는지 대조한다. 이미지 접근 실패·경로 불일치·GPU 할당량 부족은 설명용 반례로 표시한다. 생성은 하지 않는다. |

**확인용 표:** 원본 위치 / 내부 입력 경로 / 이미지 / Command / GPU·노드 / 출력 위치 / 접근 권한. 저장된 HTML의 선택지는 현재 모든 SCP 계정에서 제공되는 자원 목록의 증거가 아니다.

## 3편 · Spot Training Job과 복구 조건

**고유 목표:** 같은 Job에서 Spot을 선택할 때 달라지는 대기·중단·재개 조건을 이해한다. 2편의 공통 필드는 반복 설명하지 않는다.

| 목표 시각 | 새 콘텐츠와 화면 |
|---|---|
| 00:00–05:00 | 저장된 Spot 생성 화면의 학습 형태를 2편의 On-Demand 화면과 비교한다. 마감이 엄격한 작업과 중단을 감수할 수 있는 실험을 사례로 들어 완료까지의 시간과 실제 GPU 사용 시간을 분리한다. |
| 05:00–10:00 | Spot 화면의 Job Failover 사용 불가 표시를 읽는다. 공식 설명의 Spot 중단·재개와 GPU 하드웨어 장애 Failover를 다른 사건으로 분류한다. 코드·설정 오류는 GPU 재배치로 고쳐지지 않는다고 설명한다. |
| 10:00–15:00 | 가상 60분 학습에서 10분마다 저장하는 경우와 30분마다 저장하는 경우를 그린다. 다음 저장 직전 회수되면 각각 최대 약 10분·30분의 완료한 계산을 다시 해야 할 수 있다. 저장 I/O, 복원 시간, 자원 대기는 별도 비용이다. 수치는 실제 Spot 중단 실측이 아닌 간격 계산 예시다. |
| 15:00–20:00 | 원본 demo checkpoint-10의 trainer_state.json, optimizer.pt, scheduler.pt, rng_state.pth를 보여 준다. best_global_step 10과 파일 존재는 저장 증거다. 다른 자원에서의 복원 성공이나 Spot 중단 후 이어서 학습했다는 증거는 없다고 명시한다. |

## 4편 · 상태와 실제 로그로 실행 진단

**고유 목표:** 실행 설정·상태·로그를 연결해 경고, 진행, 실패, 완료를 구분한다. 성능 판정은 5편에서 한다.

| 목표 시각 | 새 콘텐츠와 화면 |
|---|---|
| 00:00–05:00 | 목록의 준비·대기·실행·종료 상태와 상세·모니터링·로그의 역할을 연결한다. 원본 demo와 텍스트 Job이 모두 Completed여도 서로 다른 코드·입력이라는 사실을 이름·ID·Command로 확인한다. |
| 05:00–10:00 | 원본 demo 로그에서 dataset/train.jsonl과 기반 모델 다운로드를 찾고, trainable params 1,634,304 / 전체 5,124,812,320 / 0.0319%를 읽는다. 전체 가중치 학습으로 소개하지 않는다. |
| 10:00–15:00 | 원본 demo의 max_steps 10, 짧은 epoch 진행, 어댑터·체크포인트 업로드, Training and output upload completed를 순서대로 확인한다. 이로부터 실행·업로드 완료를 판단하되 품질 향상은 주장하지 않는다. |
| 15:00–20:00 | 텍스트 Job의 classifier.bias·classifier.weight 신규 초기화 경고와 epoch 1·2 loss 로그를 보여 준다. 경고와 실패를 구별한다. 가져온 로그의 time 필드는 비어 있고 GPU 시계열은 미보존이므로 실행 시각·사용률 그래프를 지어내지 않는다. |

**진단 반례:** 실제 보존 로그에 없는 입력 경로 오류·레지스트리 권한 오류는 가상 사례로 표시한다. 오류 원인마다 확인할 설정이 다르며 무조건 재시도하지 않는다.

## 5편 · 평가와 추론 인계

**고유 목표:** 실행 완료, 품질 향상, 후속 추론 가능성을 서로 다른 주장으로 검증한다.

| 목표 시각 | 새 콘텐츠와 화면 |
|---|---|
| 00:00–05:00 | 텍스트 Job의 before.json·after.json·comparison.json을 연다. test 700건의 정확도 16.0%→85.29%, 69.29%포인트 개선과 macro-F1을 읽는다. validation 420건의 epoch별 수치와 test 결과를 같은 분할로 취급하지 않는다. |
| 05:00–10:00 | 이미지 Job의 test 2,000건, 11.2%→86.2%를 읽고 confusion_matrix.json을 연다. 코트 200건 중 135건 정답·32건 풀오버·20건 셔츠, 셔츠 200건 중 119건 정답·34건 티셔츠/상의·20건 풀오버를 보여 준다. 전체 정확도만으로는 범주별 오류가 보이지 않는다. |
| 10:00–15:00 | 원본 demo의 metrics/baseline.json과 metrics/finetuned.json을 비교한다. 둘 다 20개 샘플 intent accuracy 5%, macro-F1 약 0.0370이다. 학습·업로드 완료와 이 평가에서의 품질 개선 없음은 동시에 참일 수 있다. 입력 기반 모델과 출력 LoRA 어댑터를 구별한다. |
| 15:00–20:00 | 추론 인계표를 만든다. 텍스트는 가중치·토크나이저·라벨 설정과 제목 토큰화(max_length 64), 이미지는 model.pt·CNN 정의·픽셀 /255 전처리, 원본 demo는 기반 모델 revision·어댑터·토크나이저·채팅 템플릿을 함께 확인한다. 학습 후 재로딩 기록과 실제 추론 서비스 배포·요청 출력 검증을 구분한다. |

**근거:** [텍스트 학습 코드](../sat-8h/train_text.py), [이미지 학습 코드](../sat-8h/train_image.py), 보존된 결과 파일. 텍스트·이미지의 checkpoint_reload_verified: true는 학습 후 저장 모델을 다시 읽어 test한 기록이다. 외부 API 추론이나 SCP SAT 서빙 기능의 검증이 아니다. 모델 이동에는 형식·라이선스·권한·런타임을 추가 확인한다.

## 6편 · SAT·SageMaker·Bedrock 실무 선택

**고유 목표:** 사용자 코드 실행, 지원 기반 모델 조정, 중단 허용 작업의 세 요구사항에 맞는 후보를 고르고 미확인 조건을 남긴다.

| 목표 시각 | 새 콘텐츠와 화면 |
|---|---|
| 00:00–05:00 | [비교표](SERVICE_COMPARISON.md)의 목적·코드 자유도·스토리지 행을 읽는다. 기존 train.py와 자체 이미지가 필요한 요구에는 SAT·SageMaker가 후보이고 Bedrock 파인튜닝은 임의 코드를 실행하는 방식이 아님을 설명한다. SAT BYOC는 계정·리전의 실제 제공 여부를 확인해야 한다. |
| 05:00–10:00 | 요구 A: 기존 PyTorch 코드·모델 파일 유지. SAT의 GPU 할당량·스토리지·이미지 접근과 SageMaker의 IAM·S3·네트워크 조건을 나란히 확인한다. 파일 접근과 제품 차원의 범용 반출 지원을 구분한다. |
| 10:00–15:00 | 요구 B: 지원 기반 모델을 규격 데이터로 조정해 Bedrock에서 추론. 지원 모델·리전·데이터 형식·맞춤 모델 사용 비용을 확인한다. 일반 가중치 파일 반출이 필수라면 선택을 다시 검토한다. |
| 15:00–20:00 | 요구 C: 중단 가능한 긴 학습. SAT Spot 화면의 Failover 제한과 공식 설명의 적용 범위를 함께 적는다. SageMaker Managed Spot의 체크포인트 코드·최대 대기 한도·On-Demand 자동 전환 부재를 확인한다. 동일 작업과 성공 기준의 견적 없이 가격 우열을 단정하지 않는다. |

## 제작 완료 판정

시범 녹화 한 편의 실제 재생 시간과 정보 밀도를 측정한다. 장면별 새 개념·사례·근거가 부족하면 대사를 반복하지 않고 내용을 조정하거나 5편으로 축소한다. 녹화 파일이 없으므로 현재 모든 편의 20분 완료 판정은 보류한다.
