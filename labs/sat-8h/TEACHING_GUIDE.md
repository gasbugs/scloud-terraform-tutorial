# SAT Training Job 강의·실습 교안 — 20분 × 8차수

발표용 화면 원고는 [SLIDE_DECK.md](SLIDE_DECK.md)에 있다. 총 160분. 1·5차수는 이론, 2~4·6~8차수는 실습이다. 강사는 **아래의 발화 문장과 질문을 그대로 사용**하고, 남은 시간은 표에 지정한 화면 관찰·학습자 답변·실습 확인에 사용한다. 실제 학습은 이미 AWS G6 Docker에서 검증된 기록을 읽는다. 이 수업에서 SCP SAT Job을 새로 제출하거나 G6를 켜지 않는다.

## 강사 준비: 수업 시작 전

1. Windows 브라우저에서 [로컬 Training Job 목록](http://127.0.0.1:8080/local#jobs)을 연다. 목록과 각 상세 페이지가 열리는지 확인한다. 로컬 서버가 내려갔다면 저장소 `sat-job-local`에서 `docker compose up -d --build`로 시작한다.
2. 실습 파일은 이 저장소의 `labs/sat-8h/samples/`, 보존된 입력은 `.state/sat-8h/bundle/`, G6 출력은 `.state/sat-8h/g6-results/`에 있다. `.state`는 로컬에만 보관되는 자료이므로 학습자에게 파일 접근을 제공할 계획이면 강의 전에 확인한다. 파일 접근이 어렵다면 동일 산출물을 로컬 Job의 **결과 파일** 탭에서 보여 준다.
3. 고정 Job 링크: [원본 demo](http://127.0.0.1:8080/local#jobs/b669419947d55d6991620cdf9bbcaa1f/details), [한국어 YNAT](http://127.0.0.1:8080/local#jobs/2dd8760c5b7b55dc8d440c0d18ad2a4e/details), [Fashion-MNIST](http://127.0.0.1:8080/local#jobs/cb0e433e77965ac9ad283d14027ed2df/details). [LLM03 LoRA](http://127.0.0.1:8080/local#jobs/b9f0f2adfa275db29d4b2562e9686258/details)는 심화 예시이며 필수 차수에 넣지 않는다.
4. 로컬 사이트는 **가져온 AWS G6 실행 기록**을 보여 준다. 사이트에서 새 GPU 학습이 일어나는 것처럼 말하지 않는다. 모니터링 탭에 과거 GPU 시계열이 없으면 없는 그대로 보여 준다. 성능값은 `comparison.json`에서 읽는다.
5. 이론의 기본 근거는 `scp_sat_videos/SCP Simple AI Training 상품설명회 영상_261027_audio_only.txt`(아래 **상품설명회**)와 `scp_sat_videos/[KR] AI워크로드를 위한 SCP GPUaaS 아키텍처 설계_2610_audio_only.txt`(아래 **아키텍처 강의**)다. 자동 전사 검수 범위는 `scp_sat_videos/전사본_검수내역.md`에 적혀 있다. 현재 상품 기능·요금의 확정 근거로 전사만 사용하지 않는다.

## 1차수 · 0–20분 · 이론: Training Job이 입출력을 처리하는 방식

**교안 화면 1:** 제목 `코드를 어디에서 실행하고 결과를 어디로 돌려받는가?` 아래에 `입력 데이터 + 학습 코드/이미지 → Job 설정 → GPU 학습 → 로그·모델·지표`를 한 줄로 보여 준다. **화면 2:** 원본 demo 상세 정보의 Command·이미지·Mount Path 필드를 보여 준다. **화면 3:** 결과 파일 탭으로 이동한다.

| 시간 | 강사 진행·발화 스크립트 | 학습자 확인 |
|---|---|---|
| 0–5분 | “오늘 보는 것은 VM에 로그인해서 GPU 명령을 직접 치는 순서가 아닙니다. SAT에서 사용자는 학습 데이터, 코드가 들어 있는 컨테이너 이미지, 실행 명령을 준비해 Job으로 제출합니다. 상품설명회에서는 데이터 사이언티스트가 인프라를 직접 구성하는 부담을 줄이는 것이 이 서비스의 목적이라고 설명합니다. 그렇다고 코드 자체가 사라지는 것은 아닙니다. 여러분의 `train.py`와 입력 경로는 여전히 필요합니다.” 화면 1을 따라 세 준비물을 학습자에게 말하게 한다. | 세 준비물: 데이터, 학습 코드/이미지, 실행 설정. |
| 5–10분 | “상품설명회 02:02부터는 준비물을 GPU 클러스터에서 실행하고 결과를 사용자의 Object Storage에 저장한다고 설명합니다. 06:17부터는 Object Storage의 입력을 고성능 File Storage로 복사해 학습에 연결하는 흐름을 보여 줍니다. 여기서 **입력의 위치**와 **컨테이너 내부 경로**는 구분해야 합니다. 코드가 `/bundle/text/train.jsonl`을 읽도록 만들었는데 마운트 위치가 다르면 학습은 실패합니다.” 화면 2에서 명령·마운트 경로를 짚고 “어느 값이 경로인가?” 묻는다. | `Command`는 실행 명령, `Mount Path`는 컨테이너가 보는 데이터 위치. |
| 10–15분 | “Job 제출 이후에는 데이터 연결, GPU 배치, 컨테이너 실행, 결과 저장의 순서가 이어집니다. 학습자는 Job 상세에서 상태, 로그, 결과를 확인합니다. 로그는 **진행 과정**, 모델 파일은 **산출물**, 평가값은 **성능 근거**입니다. 로그의 `Completed`만 보고 모델 품질까지 좋다고 말할 수는 없습니다.” 결과 파일 탭에서 `comparison.json`과 모델 파일을 구분한다. | `Completed`와 좋은 평가값의 차이를 한 문장으로 답한다. |
| 15–20분 | 학습자에게 종이에 `입력 원본 → 실행 시 읽는 경로 → 학습 명령 → 저장된 결과` 네 칸을 그리게 한다. “우리 로컬 사이트는 G6의 보존 결과를 보여 주는 교육용 화면입니다. SCP에서 실제 제출한 Job이라는 뜻은 아닙니다. 다음 차수에서는 실제 원본 demo 결과에서 이 네 칸을 채웁니다.” 2명을 지명해 칸을 읽게 한다. | Job 흐름 4칸을 완성한다. |

**전사 근거:** 상품설명회 00:09–02:02(서비스 목적), 02:02–03:20(입력·이미지·GPU·결과), 06:17–07:16(스토리지와 실행 흐름). 아키텍처 강의 03:36–07:48은 보조 설명이다. **강사 주의:** “완전 관리형”이라는 상품 설명을 AWS G6 Docker 실습의 실제 동작이라고 바꿔 말하지 않는다.

## 3차수 · 40–60분 · 실습: 한국어 텍스트 입력 검증

**교안 화면:** `YNAT 제목 → 7개 주제`, [텍스트 샘플](samples/text.jsonl), 입력 매니페스트 `.state/sat-8h/bundle/text/manifest.json`. 공개 원본에서 준비한 번들은 train 2,100건, validation 420건, test 700건이다.

| 시간 | 강사 진행·발화 스크립트 | 학습자 작업·정답 확인 |
|---|---|---|
| 0–5분 | “뉴스 제목 하나가 입력이고 0~6의 정수 라벨이 정답입니다. 샘플의 `title`과 `label`을 읽으세요. 7개 한국어 이름은 매니페스트의 `labels` 순서와 대응합니다. 예를 들어 `label: 5`를 보고 제목의 주제가 스포츠인지 확인해 보세요.” | 샘플 2건의 제목, 숫자 라벨, 한국어 라벨을 표로 쓴다. |
| 5–10분 | “매니페스트의 데이터셋 ID, revision, seed, 각 분할 건수와 SHA256을 찾으세요. 어떤 데이터로 학습했는지 재현하려면 단순한 파일 이름보다 이 정보가 중요합니다.” 파일 접근이 가능하면 아래 읽기 명령을 함께 실행한다. | `klue/klue`, seed 42, 2,100/420/700, 분할별 해시를 확인한다. |
| 10–15분 | “train은 가중치를 학습하고, validation은 체크포인트를 고르며, test는 마지막에 평가합니다. test를 보고 학습 설정을 바꾸면 평가의 의미가 약해집니다. 학습 코드에서 이 세 분할을 어디서 읽는지 찾아보세요.” | [train_text.py](train_text.py)의 split 읽기와 최종 test 평가 위치를 표시한다. |
| 15–20분 | “데이터 700건의 test가 7개 라벨에 균등하다면 라벨당 몇 건입니까? 제목 중복이 분할 간에 있으면 무엇이 문제입니까?” 답을 듣고, 준비 코드의 중복 제거·해시 검증을 보여 준다. | 라벨당 100건. 중복 누수는 평가를 부풀릴 수 있다. |

```bash
# 저장소 루트의 WSL 터미널에서 읽기 전용 확인
python3 - <<'PY'
import json
from pathlib import Path
p = Path('.state/sat-8h/bundle/text/manifest.json')
m = json.loads(p.read_text(encoding='utf-8'))
print(m['dataset'], m['dataset_revision'], m['labels'])
print({k: v['count'] for k, v in m['files'].items()})
PY
```

**완료 기준:** 입력 한 행의 구조와 7개 라벨, 분할 건수를 설명한다. `.state` 번들이 없는 학습자에게는 강사가 화면에 매니페스트를 띄워 주고, [샘플](samples/text.jsonl)로 동일한 읽기 과제를 진행한다. 새 데이터 다운로드를 수업 중 필수로 요구하지 않는다.

## 4차수 · 60–80분 · 실습: 텍스트 Job의 학습 전후 평가

**교안 화면:** [YNAT Job 상세](http://127.0.0.1:8080/local#jobs/2dd8760c5b7b55dc8d440c0d18ad2a4e/details), **로그**, [평가 비교](http://127.0.0.1:8080/local#jobs/2dd8760c5b7b55dc8d440c0d18ad2a4e/comparison), **결과 파일**.

| 시간 | 강사 진행·발화 스크립트 | 학습자 작업·정답 확인 |
|---|---|---|
| 0–5분 | “상세의 실행 명령에서 `--bundle`과 `--output`을 찾으세요. 앞의 경로는 준비한 입력, 뒤의 경로는 모델과 지표를 쓰는 출력입니다. 이 Job은 로컬에서 다시 학습한 것이 아니라 G6의 실제 실행 결과를 가져왔습니다.” | 입력 `/bundle`, 출력 `/output/text`를 적는다. |
| 5–10분 | “로그에서 1·2 epoch의 validation 결과를 찾으세요. 손실만 낮아졌다고 가장 좋은 체크포인트가 마지막이라는 뜻은 아닙니다. `val-epoch-1.json`, `val-epoch-2.json`과 `comparison.json`의 `history`를 비교하세요.” | epoch 1의 validation macro-F1 약 0.8525가 epoch 2의 약 0.8353보다 높음을 확인한다. |
| 10–15분 | “평가 비교에서 test 700건의 정확도 16.0%가 85.29%가 됐고 macro-F1은 약 0.1268에서 0.8514가 됐습니다. 개선 폭을 말할 때는 **정확도 69.29%포인트 증가**라고 하세요. 서로 다른 라벨의 성능을 함께 볼 때는 macro-F1이 왜 도움이 되는지 생각해 봅니다.” | 16.0→85.29%, 0.1268→0.8514, 700건을 표로 적는다. |
| 15–20분 | “결과 파일에서 `comparison.json`, `model/model.safetensors`, `val-epoch-1.json`을 열어 각각 지표, 가중치, 선택 근거를 찾으세요. 분류 헤드는 학습 전 무작위였으므로 이 차이를 외부 모델 순위로 해석하지 않습니다.” | 세 파일의 역할과 `checkpoint_reload_verified: true`를 기록한다. |

**완료 기준:** 학습 전후 수치, 검증으로 선택한 체크포인트, 저장된 모델 파일을 실제 화면에서 짚어 설명한다.

## 5차수 · 80–100분 · 이론: Job 운영 방식과 결과를 읽는 법

**교안 화면 1:** `온디맨드 / 스팟` 두 열(자원 확보, 대기·중단 가능성, 적합한 작업). **화면 2:** Job 생성 시 `학습 형태 → 리소스 → 이미지 → Command → 스토리지` 설정 순서. **화면 3:** Job 상세의 모니터링·로그·결과 파일 탭.

| 시간 | 강사 진행·발화 스크립트 | 학습자 확인 |
|---|---|---|
| 0–5분 | “상품설명회는 온디맨드를 확보한 GPU로 실행하는 형태, 스팟을 유휴 GPU를 사용하는 형태로 설명합니다. 스팟은 자원 상황에 따라 시작을 기다리거나 작업이 취소될 수 있습니다. 그래서 마감이 정해진 수업에서 모든 학습자가 동시에 스팟 GPU를 받아야 한다는 운영 방식은 위험합니다. 오늘은 실제 실행을 미리 검증하고 결과를 보존해 둔 이유가 여기에 있습니다.” 두 방식의 적합한 작업을 학습자에게 하나씩 말하게 한다. | 일정이 중요한 학습과 중단을 감수할 수 있는 학습을 구분한다. |

## 강사 참고: 이론 근거와 자료의 한계

- 상품설명회 음성은 SAT의 제품 개념과 Job 흐름을 설명한다. 현재 제공 기능과 가격은 시점에 따라 달라질 수 있다.
- 아키텍처 강의의 스팟 자동 재개·GPU Failover 설명은 이 수업에서 실증하지 않았다. 스팟 Job에 Failover가 제공된다고 단정하지 않는다.
- 한국어 텍스트·이미지 학습 수치의 근거는 [RESULTS.md](RESULTS.md)와 로컬 사이트의 `comparison.json`이다. LLM03 LoRA는 별도 심화 자료이며 이 160분 과정의 필수 결과로 채점하지 않는다.
