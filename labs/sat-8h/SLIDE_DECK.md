# SAT Training Job 교안 화면 · 20분 × 8차수

강사는 각 차수의 첫 화면을 약 2~5분 설명하고, 둘째 화면에서 실제 로컬 Job·파일로 전환한다. 발화와 실습 지시는 [TEACHING_GUIDE.md](TEACHING_GUIDE.md)를 따른다. 대괄호 안의 숫자는 **차수-화면**이다. 이 자료는 발표용 화면 원고이며 표의 수치는 보존된 G6 `comparison.json`에서 확인한 값이다.

---

## 1차수 · SAT Training Job의 입출력

### [1-1] 학습자는 무엇을 준비하는가?

- 학습 데이터: 모델이 읽을 입력과 정답
- 컨테이너 이미지: 실행 환경과 학습 코드
- Job 설정: GPU 규모, 실행 명령, 입력·출력 경로
- 인프라 구성 대신 Job의 입력과 결과에 집중

**질문:** 명령은 컨테이너 밖에서 실행될까, 안에서 실행될까? **답:** 컨테이너 안.

### [1-2] 데이터가 모델 파일로 바뀌는 경로

`Object Storage의 입력 → File Storage 연결 → 컨테이너의 /bundle → GPU 학습 → /output의 모델·지표·로그 → 결과 저장`

- `Completed`: 실행 상태
- `comparison.json`: 평가 근거
- 모델 가중치: 재사용할 산출물

**근거:** 상품설명회 전사 02:02–03:20, 06:17–07:16. **주의:** 이 경로는 제품 설명이다. 수업의 측정값은 AWS G6 Docker 실행 기록이다.

## 3차수 · 한국어 YNAT 입력

### [3-1] 제목 한 건의 구조

```json
{"id":"ynat-v1_train_18999","title":"손흥민 아시안게임 출전할까…대표 차출 가능성은 미지수","label":5}
```

- 입력: 한국어 뉴스 제목 `title`
- 정답: 0~6의 주제 `label`; 5는 스포츠
- 전체 라벨: IT과학, 경제, 사회, 생활문화, 세계, 스포츠, 정치

### [3-2] 분할은 세 목적을 가진다

| train | validation | test |
|---:|---:|---:|
| 2,100건 | 420건 | 700건 |
| 가중치 학습 | 체크포인트 선택 | 최종 평가 |

- 매니페스트: 데이터셋 revision, seed, 건수, SHA256
- test는 학습 설정 선택에 사용하지 않는다.

## 4차수 · 텍스트 Job의 측정값

### [4-1] 학습 전후, 같은 test 700건

| 지표 | 학습 전 | 학습 후 |
|---|---:|---:|
| 정확도 | 16.00% | 85.29% |
| macro-F1 | 0.1268 | 0.8514 |

- 정확도 증가: 69.29%포인트
- 학습 전 분류 헤드는 무작위 초기화
- 외부 모델 순위나 SAT 제품 성능으로 해석하지 않는다.

### [4-2] 어느 모델을 결과로 저장했나?

- epoch 1 validation macro-F1 ≈ 0.8525
- epoch 2 validation macro-F1 ≈ 0.8353
- 선택된 체크포인트를 다시 로드한 뒤 test 평가
- 결과: `comparison.json`, `val-epoch-*.json`, `model/model.safetensors`

[텍스트 평가 비교 열기](http://127.0.0.1:8080/local#jobs/2dd8760c5b7b55dc8d440c0d18ad2a4e/comparison)

## 5차수 · Job 운영과 결과 읽기

### [5-1] 온디맨드와 스팟을 왜 구분하는가?

| 항목 | 온디맨드 | 스팟 |
|---|---|---|
| 자원 | 확보한 GPU 자원 | 유휴 GPU 자원 |
| 시작·중단 | 확보 범위에서 계획 가능 | 대기·중단·취소 가능성 |
| 수업 운영 | 일정이 중요한 실행 | 중단을 허용할 수 있는 작업 |

**근거:** 상품설명회 전사 03:20–05:08, 09:10–10:07. **확인 필요:** 스팟의 자동 재개·Failover 범위는 이 표로 확정하지 않는다.

### [5-2] 네 탭이 답하는 질문

| 상세 | 모니터링 | 로그 | 결과 파일·평가 |
|---|---|---|---|
| 무엇을 설정했나? | 자원을 얼마나 썼나? | 어떻게 진행됐나? | 무엇이 남았고 얼마나 맞혔나? |

- 시계열 기록이 없으면 `없음`으로 표시
- 완료 상태와 모델 품질은 별도로 확인
- 중단 대비 체크포인트는 코드·저장 경로와 함께 설계

**근거:** 아키텍처 강의 전사 12:07–14:18, 15:29–17:35.

## 6차수 · 이미지 입력

### [6-1] 28×28 회색조 이미지 → 의류 10종

0 티셔츠/상의 · 1 바지 · 2 풀오버 · 3 원피스 · 4 코트 · 5 샌들 · 6 셔츠 · 7 운동화 · 8 가방 · 9 앵클부츠

- 샘플 PNG는 시각 확인용
- 학습용 배열은 `train.npz`, `val.npz`, `test.npz`
- 한국어 이름은 수업용 번역

### [6-2] 원본과 분할 확인

| train | validation | test |
|---:|---:|---:|
| 12,000건 | 1,500건 | 2,000건 |
| 클래스당 1,200건 | 클래스당 150건 | 클래스당 200건 |

- 원본 Fashion-MNIST gzip 4개 MD5 확인
- seed 42, 분할 SHA256을 매니페스트에 기록
- 입력은 픽셀, 정답은 0~9 숫자 라벨

## 8차수 · 증거 기반 결과 보고

### [8-1] 결과 보고서의 다섯 증거

1. 입력과 분할: 매니페스트, 데이터 파일
2. 실행: Command, 이미지, 로그
3. 평가: test 표본 수, 학습 전후 지표
4. 산출물: 모델 파일, 비교 JSON
5. 범위: AWS G6 Docker 검증인지 SCP SAT 제출인지

### [8-2] 종료 확인까지가 실습

- 이 수업은 보존된 결과를 읽으므로 신규 G6가 필요 없다.
- 과거 검증의 Terraform 자원 8개, EC2, EBS 삭제는 확인됐다.
- 새 GPU 실습을 실행했다면 `destroy-and-verify.sh`의 종료 증거를 남긴다.
- 없는 GPU 모니터링 시계열은 만들어 내지 않는다.
